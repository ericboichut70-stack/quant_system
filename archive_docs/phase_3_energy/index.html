    6. Carte fonctionnelle du sous‑système Phoebus Énergie

    Le sous‑système Énergie / Phoebus constitue la brique analytique dédiée à la mesure, la normalisation et l’exploitation de l’énergie de marché. Il s’intègre au cœur quant en tant que module de signal avancé, utilisé dans :

    la préparation des données,

    la génération de features,

    la détection de régimes,

    la stratégie,

    la robustesse et la calibration.

    Cette section présente :

    la carte fonctionnelle détaillée,

    l’architecture cible,

    les interactions avec le cœur quant,

    les tests institutionnels,

    les recommandations de stabilisation.

    6.1. Carte fonctionnelle détaillée 6.1.1. Acquisition & Préparation des données énergie Rôle :

    charger les données nécessaires au calcul énergétique,

    nettoyer et normaliser les séries,

    détecter anomalies et discontinuités,

    préparer les colonnes énergie.

    Sources typiques :

    data/donnees_or_1m.csv, donnees_or_1h.csv

    data/200_DATA_CLONE_B_ENERGIE.csv

    data/signals_global.csv

    Tests associés :

    test_energy_integration.py

    6.1.2. Calculs énergétiques bruts Rôle :

    produire les mesures d’énergie élémentaires,

    dériver les composantes dynamiques (variation, accélération, dissipation),

    générer les signaux bruts.

    Fonctions typiques :

    énergie instantanée

    énergie cumulée

    énergie directionnelle

    énergie de rupture

    énergie de compression

    Tests associés :

    test_energy_module.py

    6.1.3. Normalisation & Stabilisation (Phase 3.2.1) Rôle :

    transformer les mesures brutes en signaux normalisés,

    garantir la comparabilité inter‑actifs et inter‑timeframes,

    stabiliser les valeurs extrêmes.

    Objectifs Phase 3.2.1 :

    protocole unique de normalisation,

    documentation complète,

    verrouillage des tests de robustesse.

    Tests associés :

    test_phoebus_energy.py

    test_phoebus_energy_robustness.py

    6.1.4. Intégration stratégique & production de signaux Rôle :

    injecter les signaux énergie dans le cœur quant,

    combiner énergie + structure + volatilité,

    produire signaux finaux (buy/sell/hold).

    Modules cœur quant impliqués :

    signal_filter.py

    signal_predictor.py

    multi_timeframe_convergence.py

    strategy_core

    Tests associés :

    test_strategy_core.py

    test_energy_integration.py

    6.2. Architecture cible 6.2.1. Structure recommandée modules/ energy/ init.py energy_raw.py energy_normalized.py energy_features.py energy_utils.py energy_config.yaml

    tests/ energy/ test_energy_raw.py test_energy_normalized.py test_energy_features.py test_energy_integration.py

    docs/ quant_engine/ energy.md

    6.2.2. Rôles des fichiers energy_raw.py : calculs bruts, transformations élémentaires

    energy_normalized.py : normalisation institutionnelle, stabilisation

    energy_features.py : dérivations avancées, signaux composites

    energy_utils.py : helpers, gestion des fenêtres, sécurité numérique

    energy_config.yaml : paramètres institutionnels

    6.3. Intégration dans le cœur quant Pipeline de données ajout des colonnes énergie dans processed/

    intégration dans quant_engine/data.py

    Feature engineering énergie normalisée → feature ML

    énergie dérivée → feature stratégique

    Stratégie & backtest énergie → signal primaire ou secondaire

    influence sur attribution, filtrage, convergence

    6.4. Tests institutionnels Calculs bruts : test_energy_raw.py

    Normalisation : test_energy_normalized.py

    Features dérivées : test_energy_features.py

    Intégration pipeline : test_energy_integration.py

    Robustesse : test_phoebus_energy_robustness.py

    6.5. Recommandations Phase 3.2.1 isoler la normalisation dans un module dédié,

    documenter chaque transformation dans energy.md,

    créer un protocole institutionnel de normalisation,

    ajouter energy_config.yaml,

    séparer tests bruts / normalisation / features / intégration,

    vérifier cohérence inter‑timeframes,

    valider robustesse sur données bruitées.

    7. Synthèse institutionnelle

    Le sous‑système Énergie / Phoebus est une brique analytique majeure du moteur quant. L’architecture cible proposée garantit :

    une séparation claire des responsabilités,

    une normalisation institutionnelle stable,

    une intégration fluide dans le pipeline quant,

    une auditabilité complète,

    une robustesse renforcée.

    Ce document constitue la référence officielle pour la Phase 3.2.1 — Énergie normalisée.
